# The voice catalogue

`app/src/main/assets/catalog.json` lists the voices QVoice offers for
download. It is generated by `tools/catalog/make_catalog.py` from the real
archives: sizes, SHA-256 checksums, top-level folders and installed sizes are
measured, never typed. The script also checks inside every archive that each
file the manifest names exists and that the bundled espeak-ng-data is
byte-identical to the copy QVoice ships (so sharing it cannot change
pronunciation).

A voice is added only after three checks, all recorded below:

1. **Licence** — the model weights *and* the recordings it was trained on
   must allow redistribution and commercial use. Use restrictions
   (OpenRAIL-M) are shown to the user and accepted before download.
2. **Intelligibility** — the real sherpa-onnx 1.13.8 engine speaks a test
   sentence per language (every speaker of a multi-speaker model), and
   Whisper (small) transcribes it back. Character error rate (CER) 0 means a
   perfect round trip. Whisper's Devanagari output is unusable in sherpa-onnx
   (it drops tokens that split a UTF-8 character), so Hindi is checked by
   having Whisper *translate* the audio to English and counting the expected
   words, with Piper Hindi voices trained on real recordings as the control.
3. **Pitch** — median F0 per speaker, to confirm the female/male labels.

Speed was measured relative to the bundled voice of the time, Kitten nano
int8 (sandbox CPU, 2 threads); absolute numbers don't transfer to phones,
ratios do roughly — on a Galaxy M31, int8 Kitten vs Piper was 6x in both
places. Since 0.3.0 the built-in voice is the fp32 build (2.7x faster than
int8 on the same test: RTF 0.106 vs 0.289, first audio 0.18 vs 0.54 s; see
ARCHITECTURE.md D-033). The sandbox is roughly 4x faster than the M31.

### Kokoro v1.0 (fp32)

- **Why fp32, not the int8 export:** int8 sounded audibly worse (average
  spectrum correlation with fp32 only 0.93-0.97, 30-90 % more
  high-frequency noise) and ran 2.5x *slower* on the sandbox CPU.
- **Round trip:** CER 0 for all 20 American, 8 British, 3 Spanish, 1 French,
  2 Italian and 3 Portuguese speakers. Chinese: 0 for six speakers, 0.2 for
  zf_xiaobei (traditional characters in the transcript, intelligible).
  Hindi (translate method): 10-11 of 12 content words for all four
  speakers, the same as the Piper Hindi controls (11/12).
- **Left out:** Japanese (espeak-ng, which sherpa-onnx uses for Kokoro's
  Japanese, can't read kanji: CER 0.38-0.43, garbled) and zf_xiaoni
  (CER 0.67, garbled).
- **Per-language settings** (`languageConfig`): espeak-ng voice (British
  English is "en" — "en-gb" doesn't exist and yields silence), lexicon, and
  for Chinese only the jieba dictionary and the number/date/phone rules.
  Those rules turned "3:45" in English into Chinese numerals; without them
  Chinese drops its digits. Checked both ways.
- **Quality per speaker** from the author's grades (Kokoro-82M VOICES.md):
  A/A- very high (af_heart, af_bella), B-/C+ high, C/C- normal, D and below
  low; Spanish and Portuguese are ungraded (normal). af_heart leads, so it
  is the default English voice.
- **Speed:** RTF 0.39, first audio 0.54 s — faster than the bundled Kitten
  nano int8 (0.60, 0.84 s) on the sandbox CPU.
- **Memory:** ~360 MB per loaded language; see EngineHost's byte budget.

### Supertonic 3 (int8)

- **Round trip, 31 languages x 2 speakers (F1, M1):** CER 0 in en, bg, da,
  de, es, fi, fr, it, nl, pl, pt, ru, sv, tr, vi; <= 0.08 in ko, ja, cs, el,
  hr, id, lt, lv, ro, sk, sl, uk (mostly transcript quirks); ar 0.05-0.11;
  hu 0-0.13; et 0.16 (Whisper-small is weak in Estonian). Hindi (translate
  method): 10-11 of 12 for five speakers.
- Styles 0-4 are female (F0 180-220 Hz), 5-9 male (120-165 Hz).
- 44.1 kHz output. It returns audio only when a whole request is done, so
  QVoice splits text into sentences itself (engine/TextChunker.kt).
- Region tags only where a language is mainly one country's (hi-IN, ko-KR,
  ja-JP, ...). With Kokoro installed too, Hindi defaults to Supertonic
  (high) over Kokoro's C-grade Hindi voices.
- **Licence:** code MIT, model weights OpenRAIL-M with use-based
  restrictions (Attachment A). Users accept it before downloading.

### Piper (Bryce Beattie's voices)

Trained by Bryce Beattie on public-domain recordings (LibriVox, LJ Speech),
published in rhasspy/piper-voices (MIT). Kristin, Norman, Cori and LJ were
trained from scratch; John was fine-tuned from Kristin. Medium quality:
CER 0, RTF 0.05-0.07 (twelve times faster than Kitten nano int8), first
audio under 40 ms — the choice for low-end phones.

## Checked and left out

| Voice | Why |
|---|---|
| Piper voices fine-tuned from "lessac" (e.g. hi_IN-rohan) | Lessac data (Blizzard 2013) is licensed for research only; a fine-tuned model inherits it |
| Piper hi_IN pratham, priyamvada | Training data CC BY-NC-SA (non-commercial) |
| Piper en_US bryce | Fine-tuned from an unreleased voice of unknown provenance |
| Piper ljspeech-high, cori-high | Good, but 5x slower than medium (RTF 0.27-0.29) for a modest gain; candidates for a "high" tier |
| Kitten mini 0.8 | Slower than Kokoro on the sandbox (RTF 0.78, first audio 1.7 s) while sounding worse |
| Kokoro int8 | See above |
| Pocket TTS, ZipVoice | Need reference audio (voice cloning): a later slice with consent checks |
| Matcha | Needs a separate vocoder download; nothing it offers that the above don't |
| Malayalam, Tamil | No clearly licensed voice exists; see BACKLOG.md |

## Updating the catalogue

1. Download the archives into one folder (the names on the `tts-models`
   release page).
2. Edit `VOICES` in `tools/catalog/make_catalog.py`; bump `CATALOG_VERSION`
   (and a voice's manifest `version` when its files change — installed
   copies then offer an update).
3. `python tools/catalog/make_catalog.py --archives <folder>`
4. `gradle test` (CatalogJsonTest checks consistency, defaults and licences).
5. In the authoring sandbox, `QVOICE_ARCHIVES=<folder> bash tools/sandbox/verify.sh`
   also installs every real archive with the app's installer and compares
   the result with the archive.

If upstream replaces an archive, its checksum changes and downloads fail
with "The downloaded file was damaged or has changed" until the catalogue is
regenerated. Mirroring the archives in QVoice's own GitHub releases (see
BACKLOG.md) removes that dependency.
